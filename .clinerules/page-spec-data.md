# このルールについて
このルールは、以下を説目します。pageの仕様の出力を求められた際に従ってください。
- 本プロジェクトにおけるpageの仕様の考え方や分類の仕方。
- それを出力するフォーマット。

# pageの範囲
- pageの範囲から、layoutは除きます。

# pageの構成要素
## 概要
　pageは複数の構成要素からなります。そして、階層構造になります。 

```example
page
├── 検索条件の入力エリア
│   ├── 検索条件のテキストボックス
│   └── 検索ボタン
└── 結果出力エリア
    ├── 結果のリスト
    │   ├── 名前
    │   └── メールアドレス
    └── ページネーション

```
　また、「page」や「検索条件の入力エリア」は、自分の子要素をどう配置するかを決めています。「検索ボタン」は単独の者であり、子要素は持ちえません。その代わり、色やラベルなどの属性を持ちます。
　したがって、下記が必要です。
1. pageのUIを正しく構成要素に分割する
2. 構成要素ごとに正しく性質を捉えて分類する

## 構成要素の種類
| 名前 | 説明 |
| ---- | ---- |
| エリア | 子要素の配置を決定するコンポーネント。ただし「展開可能なパネル」など、自身の機能を有することもある。 |
| リスト | エリアのうち、子要素の数がデータによって決まるコンポーネント。|
| 入力 | テキストボックスなど、入力を目的としたコンポーネント。 |
| アクション | ボタンなど、処理の実行を受け付けるコンポーネント。 |
| ラベル | ひとつのデータ項目を出力するコンポーネント。|
| テーブル | 検索結果の一覧など、オブジェクト配列の出力を行うコンポーネント|
